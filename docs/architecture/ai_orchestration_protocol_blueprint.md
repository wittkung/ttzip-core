## 二、 四大专项战役调度 SOP

### 战役一：底层 C 桥接减法与安全加固 (Phase 1)
- **调度指令**：
  > “启动 Phase 1：C 桥接层大师级安全加固。请使用 `code-review` 技能扫描 `Sources/CTTZipBridge/` 下所有 `.c` 和 `.h` 文件，逐行排查以下 4 项大师级军规：
  > 1. 密码/密钥/IV 释放处是否全部使用了 `ttzip_secure_zero` / `memset_s` 安全擦除？
  > 2. 所有 64 位文件大小转 `size_t` 处是否有 Clamp 保护？
  > 3. 所有流式读取是否有 NULL 指针与短读防御？
  > 4. 是否存在重构残留的冗余宏？
  > 先输出问题清单与修改方案，待我确认后再按原子 Commit 实施。”
- **物理硬闸门**：`swift build -c release` 0 warning, 0 error。

---

### 战役二：Swift 核心热路径零分配纯化 (Phase 2)
- **调度指令**：
  > “启动 Phase 2：Swift 核心热路径纯化。请派遣 `research` 子 Agent 深入审查 `Sources/TTZipCore/Zip/` 与 `Parallel/` 下所有编解码流：
  > 1. 排查热循环内是否存在隐式 `Data(count:)` 内核页清零；
  > 2. 排查并发闭包内是否存在共享锁争用或动态对象树分配；
  > 3. 验证是否全部使用了栈上固定缓冲区或无锁对象池。
  > 修改后必须运行 `swift test --filter XCTestPerformanceMeasureTests` 证明吞吐达标。”
- **物理硬闸门**：13 项吞吐门禁 100% 达标。

---

### 战役三：架构减法与 API 反配置膨胀审查 (Phase 3)
- **调度指令**：
  > “启动 Phase 3：架构减法与反配置膨胀审查。请审查 TTZip 的公共接口与参数设计：
  > 1. 识别出哪些公开 Flag/参数是可以通过内部启发式（如根据文件大小、硬件核心数、格式特性）自动决定的？
  > 2. 将这些决策收敛到库内部，实现‘调用方零感知、默认透明高性能’；
  > 3. 清理废弃的旧接口与过度设计的模式抽象。”
- **物理硬闸门**：单元测试 100% 兼容。

---

### 战役四：全量预言机对齐与性能封板 (Phase 4)
- **调度指令**：
  > “启动 Phase 4：大师级测试体系与性能封板。
  > 1. 检查所有单元测试，凡使用硬编码常量的全部重构为对齐项目原生数学预言机（Oracle）；
  > 2. 运行全格式 46 项基准测试 `TTZIP_RUN_BENCHMARKS=1 swift test --filter AllFormatsPkSuiteTests`；
  > 3. 运行 `python3 scripts/audit_performance_regression.py` 输出优化前后的全维度比对表，断言零性能倒退。”
- **物理硬闸门**：全量 620 个测试 100% 通过，四级性能审计算法断言零性能倒退。

## 三、 执行节奏铁律

1. **不需要一次性把整个项目推倒重来**；
2. **按战役分阶段推进**：每次开启一个专注的对话，只推进一个 Phase；
3. **严格以《指南》中的物理断言为验收标准**（通过编译、通过 WERROR、通过基准测试、通过预言机校验）。
