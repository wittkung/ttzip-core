# TTZip 大师级系统工程指南 (Craftsmanship Engineering Guide)

> 向 `libarchive`、`SQLite`、`Linux Kernel` 看齐的系统工程审美、物理规范与质量法典。

---

## 一、 核心设计哲学 (The Master's Aesthetic)

```
                       ┌────────────────────────────────────────┐
                       │           Less, but Better             │
                       │   (能不暴露的宏绝不暴露，能默认做的不加参数)    │
                       └───────────────────┬────────────────────┘
                                           │
         ┌─────────────────────────────────┼────────────────────────────────┐
         │                                 │                                │
┌────────▼────────┐              ┌─────────▼────────┐             ┌─────────▼────────┐
│  零配置膨胀     │              │   重构减法与清理  │             │   悲观世界模型   │
│ (Zero Config)   │              │   (Subtractive)  │             │  (Invariant-1st) │
└─────────────────┘              └──────────────────┘             └──────────────────┘
```

1. **零配置膨胀 (Zero Configuration Creep)**：
   - 严禁为了边缘场景给上层或用户暴露开关参数。凡是内部能通过特征（如文件大小 $\ge 64\text{KB}$、非稀疏、普通文件）安全判定的，必须以内置透明启发式默认执行。
2. **20 年免维护寿命标准 (Decade-Grade Longevity)**：
   - 写任何一个 Fallback 函数或内部模块时，扪心自问：“这个实现是否足够纯粹、自包含，能在未来 10 年不依赖任何外部变动稳定运行？”
3. **重构减法铁律 (Subtractive Refactoring)**：
   - 任何重构（如内联宏变独立编译单元、老接口废弃），第一动作是**清扫冗余代码与残留作用域防御**，绝不留下历史地层。

## 二、 C / Swift 6 跨语言系统级安全与确界

1. **敏感内存防死存储消除 (Dead-Store Immunity)**：
   - 所有密码、派生 Key、IV 在释放前，严禁依赖普通 `memset` 或 Swift 变量离开作用域，必须使用 `ttzip_secure_zero`（基于 `memset_s` / `volatile` 指针）强制物理擦除。
2. **跨架构整型与溢出 Clamp 保护**：
   - 任何 64 位文件偏移/大小向 32 位 `size_t` 转换，必须前置 64 位比较与 Clamp（`min((uint64_t)len, (uint64_t)SSIZE_MAX)`），杜绝在 32 位机器或大文件下的溢出截断。
3. **流式 I/O 防短读与指针双重断言**：
   - 跨语言缓冲读取严禁乐观假设，必须严格断言 `ptr != NULL` 且 `bytes_avail >= min_required`；所有系统调用与 consume 操作必须捕获返回值并进入错误分支。
4. **C 句柄魔数生命周期 (Magic Invalidation)**：
   - 所有 C 结构体句柄首字段嵌入 `uint32_t magic`，在 `free()` 前置清零，使 UAF（Use-After-Free）和 Double-Free 在入口处被物理捕获。

## 三、 热路径性能与硬件直通法则

1. **热路径零中间堆分配 (Zero-Cost on Hot Paths)**：
   - 并行压缩/解压热循环内部严禁 `malloc`/`free`，严禁使用 Swift `Data(count:)` 触发内核页清零，必须使用线程局部对象池（TLS）或栈上临时分配。
2. **Apple Silicon 16KB 页对齐与硬件直通**：
   - 内存映射 `mmap` 与对齐分配严禁硬编码 4KB，必须对齐到系统页大小（16KB，`posix_memalign(&ptr, 16384, size)`）；
   - ARMv8/v9 ACLE CRC32、NEON SIMD 加密路径必须直通硬件指令，保留格式专属 Fast-Path 旁路。

## 四、 测试真理预言机体系 (Oracle-First)

1. **原生数学预言机优先 (Native Oracle)**：
   - 算法校验（CRC32、哈希、加解密）严禁使用硬编码常量，必须对齐项目原生绝对正确的数学预言机（如 `bitcrc32()`）。
2. **46 格式历史最优硬性能门禁 (262 项细分维度)**：
   - 任何修改必须通过全量回归基准，跌破历史最优峰值 10% 物理阻断合并。
