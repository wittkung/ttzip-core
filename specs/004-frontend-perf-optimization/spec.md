# Feature Specification: 前端性能深度优化 (Frontend Performance Optimization)

**Feature Branch**: `004-frontend-perf-optimization`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "优化前端性能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 超大归档包瞬间加载与流畅浏览 (Priority: P1)

用户打开包含数万（10,000 ~ 100,000+）个文件的巨型归档包（如开发工程源码包、数据集、系统备份归档）时，应用能够瞬间呈现目录结构，滚动、折叠与展开无任何主线程卡顿与掉帧。

**Why this priority**: 归档包浏览与层级导航是 TTZip 前端 GUI 的核心使用入口。超大归档包在视图渲染时的重复计算会导致界面白屏或无响应，直接影响核心可用性。

**Independent Test**: 导入包含 50,000 个条目的归档包，测量从点击打开到首屏 Native NSOutlineView 渲染完成的耗时，以及以 120Hz ProMotion 快速连续滚动时的帧率。

**Acceptance Scenarios**:

1. **Given** 包含 50,000+ 个条目的归档包，**When** 用户点击打开或从主页拖入，**Then** 首屏目录树在 150ms 内完成布局呈现，无主线程转菊花或无响应。
2. **Given** 已展开多级目录的超大归档视图，**When** 用户在不同文件或目录节点间快速点击选中，**Then** 选中高亮与视图重绘耗时 <= 8ms，不触发整棵树的冗余重建。
3. **Given** 归档包预览窗口已打开，**When** 用户切换窗口尺寸或切换右侧预览抽屉，**Then** 布局重绘保持 60/120 FPS，不发生瞬时卡顿。

---

### User Story 2 - 海量条目搜索与实时过滤零延迟 (Priority: P2)

用户在包含大量文件的归档包内输入关键词进行实时过滤时，搜索结果能够流式、防抖并高效反馈，输入框连续打字保持极致跟手，无输入法阻塞或按键吞字。

**Why this priority**: 快速查找是深层目录归档中定位目标文件的最常用交互，搜索时的全量字符串匹配若在主线程同步进行会导致严重的键盘输入卡顿。

**Independent Test**: 在 20,000 条目归档中快速连续输入长搜索词（如 `framework.dylib`），测试输入响应与结果渲染的平滑度。

**Acceptance Scenarios**:

1. **Given** 包含 20,000+ 文件的归档视图，**When** 用户在搜索框中连续快速键入文本，**Then** 键盘输入帧率稳定在 60/120 FPS，输入框无任何卡顿或光标跳动。
2. **Given** 正在进行的后台搜索过滤任务，**When** 用户输入新字符，**Then** 之前的过滤操作自动取消并防抖合并（100ms 窗口），最终结果在 50ms 内准确呈现。
3. **Given** 搜索结果包含数千条匹配项，**When** 用户清空搜索框回到完整目录树，**Then** 视图瞬间恢复原状且记忆历史展开折叠状态。

---

### User Story 3 - 多列分栏 (Miller Columns) 磁盘浏览与预加载 (Priority: P3)

用户在多栏文件浏览器中穿透各级深层文件夹时，各分栏目录扫描完全异步化并具备自适应内存缓存，快速横向滑动与层级跳转不阻塞 UI 渲染。

**Why this priority**: 磁盘文件管理和分栏浏览是压缩归档前置与解压后浏览的重要场景，必须提供媲美甚至超越原生 macOS Finder 的轻快响应体验。

**Independent Test**: 在层级深度 > 5 且单文件夹包含 5,000 文件的磁盘目录中快速左右切换列并排序，验证异步扫描与缓存命中率。

**Acceptance Scenarios**:

1. **Given** 含有 5,000+ 文件的本地磁盘目录，**When** 用户点击展开该分栏，**Then** 界面立即响应并以渐进方式加载条目，不发生 I/O 阻塞主线程。
2. **Given** 已经加载过的分栏目录，**When** 用户在各层级之间来回切换，**Then** 直接命中高效内存缓存实现 0ms 瞬间显示。
3. **Given** 多列分栏同时展开，**When** 切换不同排序规则（如按体积、修改时间、文件类型），**Then** 排序计算在后台异步完成并在 20ms 内平滑更新当前列。

---

### User Story 4 - 高频任务进度与事件流驱动下的 UI 解耦 (Priority: P4)

在执行超高吞吐压缩/解压（如每秒处理数千个小文件）时，高频的进度更新与事件广播不造成主线程消息队列积压，界面依然能够自如操作其他交互。

**Why this priority**: TTZip 引擎层拥有极高的吞吐能力，若前端无节制接收高频进度通知刷新 `@Published` 属性，会导致 SwiftUI 视图以每秒数百次触发 body 计算，拖垮主线程。

**Independent Test**: 运行 500 个小文件的快速压缩与解压，监测主线程 CPU 占用率与 UI 交互响应度。

**Acceptance Scenarios**:

1. **Given** 引擎正在以极高速度压缩/解压数千个文件，**When** 进度事件以 > 1000 次/秒产生，**Then** 前端 UI 进度刷新率自动节流至 30~60Hz，主线程 CPU 占用维持在合理区间。
2. **Given** 正在进行大文件压缩，**When** 用户在主界面切换标签页、查看密码库或调整设置，**Then** 界面交互无延迟，无点击无响应现象。

---

### Edge Cases

- **空归档与异常数据**: 遇到包含 0 个文件、损坏头部或含有循环符号链接的归档，前端优雅显示空状态/错误提示，不陷入死循环计算。
- **超深层级递归目录**: 遇到目录嵌套深度超过 50 层的归档，目录树构建与展开不会导致栈溢出或内存崩溃。
- **高并发快速销毁**: 用户在目录尚未完成异步扫描或搜索未结束时迅速关闭视图或切换归档，所有正在运行的后台 Task 必须立即被妥善 Cancel，无内存泄露与野指针回调。
- **高频内存压力**: 在连续浏览数十个超大归档后，内存占用能够及时释放回收，无未解构的树形节点或观察者持有。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (目录树结构计算离线化与 Memoization)**: 归档树构建（`ArchiveTreeBuilder.buildTree`）严禁在 SwiftUI View 的 computed property 中随每次渲染重复执行。必须将构建逻辑移至后台异步并发或在数据源变更时执行一次性缓存记忆。
- **FR-002 (搜索过滤防抖与异步流)**: 归档内搜索和文件列表过滤必须引入防抖机制（100ms Debounce）并在后台线程计算，匹配完成后切回 `@MainActor` 仅更新展示数据。
- **FR-003 (分栏浏览异步扫描与 LRU 缓存)**: Miller Column 目录扫描与元数据排序必须完全在 `Task.detached(priority: .userInitiated)` 中执行，分栏条目使用有界 LRU 缓存避免无限制内存膨胀。
- **FR-004 (高频进度与事件节流协调器)**: 针对 `ArchiveProgressBroadcaster` 与中介者高频进度推送，前端状态层必须提供帧率对齐的节流调度（如基于 `Combine` / `AsyncSequence` 采样节流），限制主线程 UI 重绘频率不超过 60 FPS。
- **FR-005 (零主线程同步 I/O 阻塞)**: 所有涉及磁盘读取、文件类型探测、尺寸统计及媒体缩略图生成的 I/O 操作均必须在非主线程执行。
- **FR-006 (选择与交互轻量化响应)**: 节点选择、快捷键导航（上下左右光标）、多选操作必须实现局部状态更新，禁止触发全量视图结构重新装配。

### Key Entities

- **ArchiveTreeStore**: 归档目录树状态持有与记忆体容器，负责非主线程的异步树构建、节点索引、过滤结果缓存与展开状态持久化。
- **ThrottledProgressPublisher**: 进度与事件节流协调管道，对高频推送进行时钟对齐与采样合并。
- **ExplorerCacheManager**: 分栏浏览与磁盘目录项的 LRU 缓存管理器，提供线程安全的快速读取与基于目录变更通知的增量失效。
- **SearchFilterPipeline**: 异步搜索管线，支持防抖输入、后台过滤、取消过时计算及流式回传匹配项。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (首屏秒开)**: 50,000 个条目的超大归档在打开后，首屏 Native Outline View 渲染就绪时间 <= 150ms。
- **SC-002 (滚动丝滑度)**: 超大归档与千项磁盘目录浏览在滚动操作中帧率维持在 60 FPS（在支持 ProMotion 设备上达 120 FPS），单帧渲染时间 <= 16.6ms（ProMotion 下 <= 8.3ms）。
- **SC-003 (搜索无打字卡顿)**: 20,000 个条目的归档包搜索，键入响应延迟 <= 8ms，过滤结果在停止键入后 <= 50ms 内平滑呈现。
- **SC-004 (进度刷新主线程降载)**: 高频压缩/解压过程中，前端 UI 相关的 CPU 占用率降低 >= 50%，主线程事件循环延迟 <= 10ms。
- **SC-005 (内存占用优化)**: 连续打开/切换 10 个 50,000+ 条目的归档后，无额外驻留泄漏，内存占用保持在合理水位。
- **SC-006 (零功能与架构倒退)**: 全量 525+ 单元测试和性能门禁测试 100% 通过，不破坏现有 28 种设计模式体系和 C 底层引擎。

## Assumptions

- 运行环境为 macOS 14.0+，支持 Swift 6.0 结构化并发与 `@MainActor` 隔离模型。
- 底层 C 静态库编解码速度与性能门禁不受前端修改影响，严格遵守项目性能铁律与 Zip 引擎冻结规则。
- 原生 AppKit 桥接组件（如 `NativeArchiveOutlineView`）继续作为大列表树的核心渲染基础设施，保持与 macOS Finder 一致的交互手感。
