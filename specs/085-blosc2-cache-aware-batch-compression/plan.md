# Implementation Plan: Blosc2 Cache-Aware Batch Compression Pipeline

**Branch**: `085-blosc2-cache-aware-batch-compression` | **Date**: 2026-08-18 | **Spec**: [`spec.md`](file:///Users/kevintung/Documents/dev/TTZip/specs/085-blosc2-cache-aware-batch-compression/spec.md)

---

## Summary

This feature adapts the hierarchical L1/L2 cache-aware two-level partitioning model from `c-blosc2` (Super-chunk -> Chunk -> Block) to TTZip's batch small-file archiving pipeline. By aggregating small files (<64KB) into 128KB–256KB cache-optimal `BatchWorkUnit` slices, pre-allocating a 128-byte cache-line aligned memory arena, reusing thread-local `libdeflate_compressor` instances, and reducing GCD over-dispatch and VFS syscall storms by >90%, TTZip achieves accelerated small-file compression throughput while maintaining 100% binary interoperability with standard ZIP, 7Z, and TAR specifications.

---

## Technical Context

**Language/Version**: Swift 6.0 (`swift-tools-version: 6.0`) + C11 / POSIX APIs.
**Primary Dependencies**: `libdeflate` (in-process static C library), ARM NEON SIMD intrinsics, Apple GCD (`dispatch_apply`).
**Storage**: Direct in-process I/O via `openat`, `pread`, `pwrite_all`, `posix_memalign`.
**Testing**: `swift test` (XCTest), `XCTestPerformanceMeasureTests`, `ArchiveWriterTests`.
**Target Platform**: macOS 14.0+ (Apple Silicon NEON prioritized, Intel x86_64 compatible).
**Project Type**: High-performance native archiving engine & desktop application.
**Performance Goals**: Batch small files (500 files, 4KB each) >= 50 MB/s (Debug) / >= 70 MB/s (Release); zero regression across all 10 throughput floors.
**Constraints**: Zero intermediate heap allocations on hot paths; zero shared locks in parallel loops; strictly bounded memory arena (<128MB); 100% standard archive compatibility.
**Scale/Scope**: Scales gracefully from small asset folders (500 files) to massive codebases (100,000+ files).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **Zero-Cost Abstraction on Hot Paths**: No dynamic object trees or heap alloc/free inside compression loops.
- [x] **No Shared Locks in Parallel Loops**: TLS compressor reuse without `NSLock` or `pthread_mutex`.
- [x] **Fast-Path Bypass Preservation**: Direct bypasses for `.sevenZip`, `.store`, and single large files remain untouched.
- [x] **Hard Throughput Floors Respected**: Meets and exceeds all 10 floor baselines.
- [x] **Frozen Files Respected**: Frozen files (`ZipParallelExtractor.swift`, etc.) are completely unmodified.
- [x] **Memory Alignment Invariant**: 128-byte hardware cache-line alignment via `posix_memalign`.
- [x] **Oracle & Standard Invariant**: 100% extractable by system `/usr/bin/unzip`, `/usr/bin/tar`, `7z`.

## Phase 0: Outline & Research

- R001 [SUBAGENT:research] 《Blosc2 L1/L2 Cache-Aware 分块模型与 Apple Silicon 核心私有缓存匹配研究》：查阅 Blosc2 源码中的 `compute_blocksize` 启发式策略与 Apple Silicon P-Core 128KB L1D / 128B 缓存行拓扑，确定 128KB~256KB 批容量与 64 文件上限。
- R002 [SUBAGENT:research] 《TTZip 批量小文件 VFS 系统调用合并与无锁 Arena 内存对齐方案》：研究 500+ 个 4KB 小文件的 VFS 锁竞争与 False Sharing 根因，设计 128 字节硬件对齐的无锁 Arena 内存池与 TLS 压缩器复用机制。
- R003 [SUBAGENT:research] 《标准 ZIP/TAR/7Z 容器规范与自适应分流路由（Adaptive Size Tiering）》：研究三级分流阈值（Tier 1: <64KB 批聚合，Tier 2: 64KB~16MB 直接映射，Tier 3: >16MB 分块并行）与 PKWARE APPNOTE / POSIX ustar 标准兼容性。
