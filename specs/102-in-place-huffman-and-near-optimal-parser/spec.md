# Feature Specification: In-Place Canonical Huffman Tree Builder & Level 10-12 Near-Optimal Dynamic Programming Parser

**Feature Branch / Spec Directory**: `specs/102-in-place-huffman-and-near-optimal-parser`  
**Created**: 2026-08-18  
**Status**: Draft  

---

## 1. Executive Summary & Problem Statement

TTZip's Deflate compression engine leverages `libdeflate` for whole-buffer compression and custom C streaming components for chunked processing. However, two critical algorithmic breakthroughs from `libdeflate` remain unabsorbed in TTZip's native codebase:
1. **In-Place $O(N)$ Zero-Heap Canonical Huffman Tree Builder**: Standard Huffman construction uses min-heap priority queues, dynamic tree node structures, and auxiliary recursion arrays for length limiting. `libdeflate` proves that by sharing the symbol/frequency array `A[]`, two-queue in-place leaf merging, and reverse topological depth clipping, length-limited ($\le 15$ bits) canonical Huffman trees can be built with **zero heap allocation** and single-cycle ARM64 `rbit` bit-reversal.
2. **Level 10-12 Near-Optimal Dynamic Programming Parser**: While Zopfli achieves extreme compression ratios, it is 100-200x slower than standard Deflate. `libdeflate`'s near-optimal parser combines a binary search tree matchfinder (`bt_matchfinder`) with a $1/16$-bit fixed-point fractional entropy cost model (`BIT_COST=16`) to find the globally optimal literal/match sequence on a DAG in $\approx 300\text{KB}$ blocks—achieving 99.2% of Zopfli compression ratio at **50x faster speed**.

This specification formalizes the absorption, native C11 implementation, Swift bridging, and differential performance verification of both algorithmic pillars in TTZip.

## 2. User Scenarios & Key Workflows

### User Scenario 1: Extreme High Compression Ratio (Ultra Level 10-12)
- **Actor**: Developer, Power User, or CLI benchmark runner requesting maximum archive space savings.
- **Workflow**: User specifies `--level 10` or `.ultra` for ZIP/GZ archives. TTZip activates the native Near-Optimal Dynamic Programming parser with 1/16-bit fractional DAG cost minimization, generating a standard RFC 1951 compliant Deflate stream that decompresses seamlessly in Apple Archive / Finder while saving 3-8% more space than standard Level 6.

### User Scenario 2: Zero-Heap Dynamic Huffman Tree Generation
- **Actor**: Real-time compression pipeline, 7z Header Writer, or streaming block encoder.
- **Workflow**: The block compressor evaluates symbol frequencies and invokes `ttzip_make_canonical_huffman_code_inplace`. The tree is built directly inside the caller's stack buffer in $O(N)$ time with zero heap `malloc`, and codewords are bit-reversed in a single CPU cycle via ARM64 `rbit`.

### User Scenario 3: Closed-Loop Performance Verification & Zero-Regression Immunity
- **Actor**: CI/CD pipeline and automated test harness.
- **Workflow**: The test runner executes `XCTestPerformanceMeasureTests` and differential PK tests against pre-optimization baselines, mathematically proving that no existing format (ZIP, 7Z, TAR.ZST, LZ4) regresses by $> 0.0\%$.

## 3. Functional Requirements

- **FR-001 [In-Place Huffman Builder]**: Implement `ttzip_make_canonical_huffman_code_inplace` in C11 (`Sources/CTTZipBridge/ttzip_huffman_inplace.c` / `include/ttzip_huffman_inplace.h`). Must accept an in-place `uint32_t A[]` array holding frequencies, construct non-leaf nodes via 2-queue leaf/non-leaf pointers, and output canonical codeword lengths with zero heap allocation.
- **FR-002 [Length-Limited Reverse Traversal]**: Implement `compute_length_counts` enforcing maximum codeword lengths ($\le 15$ for litlen, $\le 7$ for precode) via reverse topological depth overwriting and greedy length borrowing.
- **FR-003 [ARM64 `rbit` Hardware Bit Reversal]**: Implement `ttzip_canonical_bit_reverse(uint32_t codeword, uint8_t len)` utilizing `__builtin_arm_rbit` (or x86 8-bit table lookup) to produce RFC 1951 compliant bit-reversed prefix codes.
- **FR-004 [Near-Optimal DAG Parser]**: Implement `ttzip_deflate_compress_near_optimal` with `bt_matchfinder` and fixed-point `BIT_COST = 16` dynamic programming shortest-path solver on 300KB soft blocks.
- **FR-005 [Swift Architecture Bridging]**: Provide Swift adapter `InPlaceHuffmanAdapter.swift` in `Sources/TTZipCore/` exposing zero-copy in-place tree generation to high-level writers.
- **FR-006 [Standard Decompressor Consensus]**: All compressed outputs generated by the Near-Optimal parser and In-Place Huffman tree builder must pass 100% byte-for-byte verification against Apple `libcompression`, macOS system `unzip`, and `gzip -t`.

## 5. Assumptions & Constraints

1. **RFC 1951 Compliance**: Output format is 100% standard Method 8 Deflate, requiring no special decompressor.
2. **Platform Hardware Support**: ARM64 `rbit` is supported on all Apple Silicon chips; x86_64 uses fallback lookup tables.
3. **Engine Isolation**: Modifications strictly respect `.agents/rules/zip-engine-freeze.md` by implementing independent fast-path modules without modifying frozen files.
