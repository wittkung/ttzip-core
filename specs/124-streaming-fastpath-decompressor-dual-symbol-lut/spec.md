## Clarifications

### Session 2026-08-19
- **Q1: What is the primary throughput bottleneck in single-core Deflate decompression?**
  - **Decision**: Bit-by-bit bitstream decoding and individual byte copies during match replication. Addressing this requires a 10-bit dual-symbol LUT and 16-byte SIMD match copy.
- **Q2: How should overlapping matches (e.g. RLE repeating patterns where offset < 8) be handled?**
  - **Decision**: Use 8-byte/16-byte SWAR pattern replication (replicate 1/2/4 bytes to 8 bytes, then copy in 8-byte steps) to avoid scalar byte-by-byte loops.
- **Q3: How to guarantee safety when output buffer is near the boundary?**
  - **Decision**: Use a 32-byte fast-path buffer margin (`out_next + 32 <= out_end`). When within 32 bytes of `out_end`, fall back to safe scalar copy.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Dual-Symbol Direct LUT Decoding (Priority: P1)

As a user extracting ZIP archives containing text, code, or repetitive data, I want decompression to process up to two literal symbols per lookup cycle, so that single-core decompression throughput exceeds 8,000 MB/s.

**Why this priority**: Decompression is the most common user-facing archive operation.

**Independent Test**: Evaluated via single-core decompression benchmarks against standard Deflate streams.

**Acceptance Scenarios**:
1. **Given** a stream of short literal codewords ($\le 5\text{ bits}$), **When** looked up in the 10-bit LUT, **Then** 2 bytes are decoded and written in a single step.
2. **Given** any valid Deflate block, **When** decompressed, **Then** output byte stream matches original uncompressed data 100%.

---

### User Story 2 - Vectorized SIMD Match Replicator (Priority: P2)

As the decompression engine replicating LZ77 length/offset matches, I want to use ARM NEON 16-byte stores and SWAR overlapping pattern multipliers, so that match copy operates at memory bandwidth speeds.

**Why this priority**: Match replication accounts for 40%~60% of decompression execution time.

**Independent Test**: Verified across Silesia corpus text, binary, and log payloads.

**Acceptance Scenarios**:
1. **Given** a match with `offset >= 16` and `len >= 16`, **When** executed, **Then** NEON 128-bit load/stores replicate the data without byte-level branching.
2. **Given** a match with `offset < 8` (e.g. run-length byte or 2-byte word), **When** executed, **Then** the pattern is expanded into a 64-bit word and written with 64-bit stores.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST implement a 10-bit primary decode table supporting single and dual literal symbol decoding.
- **FR-002**: System MUST implement branchless bitstream replenishment using 64-bit unaligned memory loads.
- **FR-003**: System MUST implement SIMD NEON 16-byte and SWAR 8-byte match copy routines.
- **FR-004**: System MUST support overlapping match replication for $1 \le offset < 8$ with zero undefined behavior.
- **FR-005**: System MUST include a safe boundary fallback when within 32 bytes of output capacity.
