# Data Model: C Test Harness & Runner Telemetry

**Feature**: `154-c-test-harness-migration`  
**Date**: 2026-08-20  
**Status**: Completed  

---

## 1. Entities & Data Structures

### 1.1 `TestCaseResult`
Represents the execution outcome and diagnostic metrics of a single test case function.

| Field | Type | Required | Description | Constraints / Validation |
| :--- | :--- | :--- | :--- | :--- |
| `name` | `string` | Yes | Unique identifier/name of the test case | Non-empty, alphanumeric + underscores |
| `suite_name` | `string` | Yes | Name of the parent test suite | Non-empty |
| `status` | `enum` | Yes | Outcome status | Enum: `["passed", "failed", "skipped"]` |
| `duration_nanos`| `integer` | Yes | Monotonic execution time in nanoseconds | `>= 0` |
| `assert_count` | `integer` | Yes | Number of assertions evaluated | `>= 0` |
| `fail_expr` | `string` | No | Expression string that failed assertion | Present only if `status == "failed"` |
| `fail_msg` | `string` | No | Formatted mismatch message | Present only if `status == "failed"` or `"skipped"` |
| `fail_file` | `string` | No | Source file path where failure occurred | Valid relative path |
| `fail_line` | `integer` | No | Source line number of failed assertion | `>= 1` |

---

### 1.2 `TestSuiteSummary`
Represents the aggregated metrics for an entire test suite execution.

| Field | Type | Required | Description | Constraints / Validation |
| :--- | :--- | :--- | :--- | :--- |
| `suite_name` | `string` | Yes | Name of the test suite | Non-empty |
| `total_tests` | `integer` | Yes | Total number of test cases executed | `>= 0` |
| `passed_tests` | `integer` | Yes | Count of passing test cases | `>= 0, <= total_tests` |
| `failed_tests` | `integer` | Yes | Count of failing test cases | `>= 0, <= total_tests` |
| `skipped_tests` | `integer` | Yes | Count of skipped test cases | `>= 0, <= total_tests` |
| `total_assertions`| `integer` | Yes | Cumulative assertion count | `>= 0` |
| `total_duration_nanos` | `integer` | Yes | Total duration of the suite in nanoseconds | `>= 0` |
| `pass_rate` | `number` | Yes | Percentage of passed tests | `0.0 <= pass_rate <= 100.0` |
| `test_cases` | `array<TestCaseResult>` | Yes | Array of individual test case results | `length == total_tests` |

---

### 1.3 `CTestRunnerReport`
The top-level telemetry report generated by `ttzip_c_test_runner`.

| Field | Type | Required | Description | Constraints / Validation |
| :--- | :--- | :--- | :--- | :--- |
| `schema_version`| `string` | Yes | Schema version | Constant `"1.0.0"` |
| `timestamp` | `string` | Yes | ISO 8601 UTC timestamp | Format: `date-time` |
| `platform` | `string` | Yes | OS and hardware architecture | e.g. `"Darwin arm64 (Apple Silicon)"` |
| `sanitizers_enabled` | `boolean` | Yes | Whether ASan/UBSan was compiled in | `true` or `false` |
| `total_suites` | `integer` | Yes | Total test suites executed | `>= 1` |
| `all_passed` | `boolean` | Yes | Global success flag | `true` if all suites passed |
| `suites` | `array<TestSuiteSummary>` | Yes | Array of test suite summaries | `length == total_suites` |

---

## 2. Invariants & Rules

1. **Sum Invariant**: For any `TestSuiteSummary`, `total_tests == passed_tests + failed_tests + skipped_tests`.
2. **Success Invariant**: `all_passed == true` if and only if `failed_tests == 0` across all suites.
3. **Zero Heap Allocation Invariant**: In C implementation, test harness metrics reside in static and stack structures without dynamic heap allocation during test case execution.
