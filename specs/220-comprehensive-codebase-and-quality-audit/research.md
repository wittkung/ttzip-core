## 1. Research Item 1: Automated SPDX Dual-License Injection Strategy

### Context & Problem
`scripts/lint_codebase_standards.sh` Step 1 requires all TTZip-authored `.swift`, `.c`, `.h`, and `.sh` files to contain:
```swift
// SPDX-License-Identifier: BSD-3-Clause OR Apache-2.0
//
// Copyright (c) 2026 Witt Kung <witt.w.kung@gmail.com>
// All rights reserved.
//
// TTZip: High-performance native archiving and compression engine for macOS.
```
Currently, 146 Swift UI and service component files under `Sources/TTZipApp/` lack this header, causing the codebase standards gate to fail.

### Decision
Implement a deterministic Python injection utility that parses existing leading comments and docstrings, prepends the standardized 7-line dual-license header if absent, and validates syntax formatting without disturbing any existing declarations or compiler directives.

### Rationale
Manual file-by-file edits across 146 files is error-prone and risks formatting churn. An idempotent script ensures exact match with `lint_codebase_standards.sh` regex rules.

### Alternatives Considered
- `sed -i` in-place insertion: Rejected due to differences between GNU sed and macOS BSD sed, which can corrupt file encodings or trailing newlines.
- Git pre-commit hook only: Rejected because repository clean state must be validated prior to staging.

## 2. Research Item 2: C-ABI Bridge Contract Synchronization & C++20 Header Hygiene

### Context & Problem
`Sources/CTTZipBridge/include/` contains:
- `ttzip_rust_glue.h` (autogenerated C11 bindings for Rust core)
- `ttzip.h` (public C API)
- `ttzip.hpp` (modern header-only C++20 wrapper)
- `module.modulemap` (Clang modulemap for Swift interop)

All exported methods must maintain exact binary interface parity, parameter naming alignment, and zero compiler warnings under `-Wall -Wextra -Wpedantic` and Swift 6 Clang importer.

### Decision
Audit all function signatures in `ttzip.h` and `ttzip.hpp` against `ttzip_rust_glue.h` to verify:
1. `TTZipStatus` enum return codes and negative error domain mapping.
2. `catch_unwind` exception-safe boundaries for all C-ABI entry points.
3. Zero non-ASCII characters in header docstrings (required by Step 2/3 of `lint_codebase_standards.sh`).

### Rationale
Prevents undefined behavior and ABI mismatch across language boundaries while maintaining 100% C/C++ compatibility.

## 3. Research Item 3: Multilingual SDK Automation & Toolchain Agnostic Test Runner

### Context & Problem
TTZip supports client SDKs across Python, Node.js, C, C++, Java/Kotlin, Dart, and .NET. In diverse local development environments, some toolchains (e.g. `dotnet`, `dart`, `javac`) may not be installed.

### Decision
Refactor `scripts/run_all_sdk_tests.sh` to implement toolchain presence detection (`command -v <tool>`):
1. **Toolchain Present**: Execute test target and assert status code 0.
2. **Toolchain Absent**: Log `[SKIP] <SDK> toolchain not found` and continue without failing the suite.
3. Emit structured TAP/JUnit summary report at completion.

### Rationale
Enables continuous local verification for core developers without mandating the installation of 7 distinct programming language toolchains.

## 4. Research Item 4: Local CI Gate Pipeline Optimization & Verification Hardening

### Context & Problem
`scripts/run_local_ci_gate.sh` is the central quality gate executing 4 stages:
1. Single-file LOC defense gate ($\le 800\text{ LOC}$)
2. Swift high-level facade & CLI suite
3. 50-point Deflate-Bench matrix gate
4. Rust industrial test suite (unit, props, fuzz, differential)

### Decision
Ensure all 4 stages can be executed independently (`--stage <name>`) or in composite (`--bail`), emitting structured JSON reports to `reports/local_ci_report.json` with execution timing for regression tracking.
