# Subtitle timeline, caching & styling contract (2026-10-17)

Status: revised for fault-tolerant stream demuxing (resolving `Subtitle cue end must follow start`), multi-format/encoding ingestion (`SRT`/`VTT`/`TTML`/`ASS`, UTF-8/UTF-16/legacy CJK), companion + directory discovery, off-main-actor budgeted pre-warming, binary-search timeline lookup, invariant subtitle positioning, and IINA-inspired style/delay/dual-track controls.

## Rust boundary & fault-tolerant stream parsing

The existing TTMediaDemux C bridge exports `ttmedia_subtitles_parse(const uint8_t *data, size_t len)`, `ttmedia_subtitles_container_request(const char *path, int64_t track, uint64_t request_id)`, `ttmedia_subtitles_container(const char *path, int64_t track)`, `ttmedia_subtitles_register_request(uint64_t request_id)` (returns `bool`: `true` if registered, `false` if rejected due to `MAX_ACTIVE_REQUESTS = 4096` capacity limit), `ttmedia_subtitles_cancel_request(uint64_t request_id)`, `ttmedia_subtitles_reclaim_request(uint64_t request_id)`, `ttmedia_subtitles_is_request_cancelled(uint64_t request_id)`, `ttmedia_subtitles_last_scanned_clusters(uint64_t request_id)`, `ttmedia_subtitles_active_request_count(void)`, `ttmedia_subtitles_pre_start_tombstone_count(void)`, `ttmedia_subtitles_completed_record_count(void)`, `ttmedia_subtitles_pending_delay_count(void)`, `ttmedia_subtitles_retained_record_count(void)`, `ttmedia_subtitles_set_request_cluster_delay_ms(uint64_t request_id, uint32_t delay_ms)`, `ttmedia_subtitles_cancel(void)`, and `ttmedia_subtitles_free(char *value)`. Input is borrowed only for the synchronous call. NULL, empty payloads, more than 50,000 cues, payloads over 4 MiB, or inputs yielding zero valid cues return an error object. The returned NUL-terminated UTF-8 JSON allocation is released exactly once with `ttmedia_subtitles_free`; NULL can be freed safely.

Success: `{"cues":[{"start":1.0,"end":2.0,"text":"Hello"}]}`. Failure: `{"error":"reason"}`. Allocation failure may return NULL. Times are seconds; active cue intervals are start-inclusive/end-exclusive. Cues are sorted by `(start, end)` and overlaps are displayed together.

### Encoding & format normalization
1. **Byte-level BOM & encoding handling**: Rust decodes UTF-8 (with or without BOM `\xEF\xBB\xBF`), UTF-16LE BOM (`\xFF\xFE`), and UTF-16BE BOM (`\xFE\xFF`) directly; Swift `ExternalSubtitleTrack.load(from:)` additionally falls back to legacy encodings (`GB18030`, `Big5`, `UTF-16`, `WindowsCP1252`, `ISOLatin1`) and re-encodes to UTF-8 before invoking Rust when raw bytes are non-UTF-8 without UTF-16 BOM. CRLF and CR line endings are normalized to `\n`.
2. **Supported external formats**:
   - **SRT & WebVTT (`.srt`, `.vtt`)**: Line-by-line streaming state machine (inspired by FFmpeg `libavformat/srtdec.c` and `webvttdec.c`). Tolerates cue bodies containing internal blank lines, WebVTT `NOTE`/`STYLE`/`REGION` blocks, numeric sequence headers, and trailing settings/coordinate tags.
   - **TTML / DFXP (`.ttml`, `.dfxp`)**: Extracts `<p begin="..." end="...">` timed paragraphs, converts `<br/>` tags to `\n`, strips nested XML tags, and decodes XML entities. Preserves original cue timestamps by default (never heuristically subtracts 1 hour when the first cue starts around `01:00:00`, avoiding corruption of legitimate late-starting subtitles; NLE timecode offsets are handled via explicit `delay` configuration or explicit metadata).
   - **ASS / SSA (`.ass`, `.ssa`)**: Parses `[Events]` `Format:` and `Dialogue:` records (`Start`, `End`, `Text`).
3. **Text sanitization**: Inline ASS override tags (`{\...}`), basic HTML/VTT styling tags (`<i>`, `<b>`, `<u>`, `<font...>`), and escaped linebreaks (`\N`, `\n`, `\h`) are sanitized into clean multi-line plain text; full `libass` vector positioning/karaoke effects are not rendered.
4. **Fault-tolerant cue finalization (FFmpeg `ff_subtitles_queue_finalize` alignment)**:
   - Cues whose sanitized text is empty are silently skipped rather than aborting the file.
   - **Zero-duration cues (`end == start`)**—commonly produced by DaVinci Resolve, WhisperX, and ASR exporters (e.g., `00:14:52,456 --> 00:14:52,456`)—are repaired during finalization: `end` is extended to `min(start + 1.5, next_later_cue.start)` (or `start + 0.8` when no later cue exists, with a minimum floor of `start + 0.25`).
   - **Reversed cues (`end < start`)** are skipped individually when other valid cues exist; the parser returns an error only if zero valid cues remain across the entire file.

## Host lifecycle, directory discovery, off-main-actor pre-warming & timeline lookup

The system file chooser (`NSOpenPanel`) and viewport drag-and-drop (`onDropFiles`) authorize `.srt`, `.vtt`, `.ttml`, `.dfxp`, `.ass`, and `.ssa` URLs. A background task holds security-scoped access while reading at most 4 MiB+1 and parsing, then closes the handle and balances scope. Replacing a load cancels its publication; cancellation or failure retains the old track.

### Companion matching & directory subtitle catalog
Same-directory subtitle files (when directory read permission is available) are partitioned into:
1. **Matched companions (`companionSubtitles`)**: Exact case-insensitive stem match or separator-prefixed language suffix (`.`, `_`, `-`).
2. **Same-directory available subtitles (`directorySubtitles`)**: All other supported subtitle files in the same folder (e.g., `Timeline 1.srt`, `Subtitle 1.srt`, `简体字幕.srt`, `Timeline 1_Subtitle 1.ttml`) are listed directly in the subtitle menu and quick settings popover so users can mount them in a single click without opening `NSOpenPanel`.

#### Explicit full load vs budgeted background pre-warming & lookup complexity
- **Timeline lookup (`ExternalSubtitleTrack.text(at:delay:)`)**: Precomputes `maxEndPrefix` and `prevHigherEndIndex` over start-sorted cues on a background thread. Lookup performs an $O(\log N)$ binary search for the `start <= effectiveTime` upper bound, then follows monotonic end-time jumps to collect overlapping active cues ($O(\log N + k)$ for $k$ overlapping cues, with worst-case $O(N)$ only when overlapping cues span the prefix).
- **Strict separation between User-Initiated Explicit Full Load (`track > 0`) and Background Pre-warm (`track == 0` or `track <= -2`)**:
  1. **User-initiated explicit full load & initial default track activation (`track > 0`)**: Used exclusively when the user explicitly selects an embedded primary/secondary subtitle track (`selectSubtitle`, `selectSecondarySubtitle`) or when initial discovery activates the single preferred default track (`activateDefaultEmbeddedTrack`). Runs without the 4.0s prewarm time budget (`deadline: None`) so the complete cue timeline across the entire movie is extracted, while checking per-request cancellation (`request_id` via `is_request_cancelled(request_id)`) at scan start, every EBML element, and every `Cluster` block boundary.
  2. **Background pre-warm (`scheduleBackgroundSubtitlePrewarm` -> `prewarmEmbeddedBatch`, `track == 0` or encoded `track <= -2`)**:
     - Runs under a shared session pre-warm budget of `prewarmBudgetSeconds = 4.0` and `maxPrewarmTracks = 8` across both external and embedded tracks.
     - External file pre-warming runs first and consumes part of the 4.0s budget and track slots.
     - Before starting embedded container pre-warming, Swift computes the **remaining time budget** `remainingBudgetMs = (deadline - CFAbsoluteTimeGetCurrent()) * 1000` (clamped to `1...4000`, never resetting to a fresh 4.0s budget; if `<= 0`, embedded pre-warm is skipped) and `remainingSlots = maxTracks - prewarmedCount`.
     - **No single-track `track > 0` bypass & strict encoding boundary validation**: Even when only 1 uncached embedded track or 1 remaining slot exists (`boundedTargets.count == 1`), background pre-warm **never** calls `track > 0`. Instead, it encodes `(targetTrackID: singleTargetID, maxTracks: boundedTargets.count, budgetMs: remainingBudgetMs)` into `track <= -2` via `SubtitlePrewarmRequestCodec` (`try_encode_prewarm_request` / `decode_container_request` in Rust). Both Swift and Rust strictly validate encoding boundaries: `Int64.min` (`i64::MIN`) is rejected via `track.checked_neg().ok_or_else(...)` and returns an `InvalidInput` error in Rust (`nil` in Swift `SubtitlePrewarmRequestCodec.decode`), never overflowing and **never falling back to batch prewarm**; reserved high bits (`(raw >> 56) != 0`) are rejected with `InvalidInput`; and unrepresentable track IDs (`<= 0` or `> UInt32.max`, e.g. `(1 << 32) + 3`) return `nil` / `None` rather than silently truncating into another track ID.
     - **Pre-warm completeness guarantee (`complete: Bool`)**: If the pre-warm budget expires or `request_id` cancellation occurs mid-scan before reaching `segment.end`, Rust marks the response as incomplete (`"complete": false`) and clears partial `trackCues` (`"trackCues": {}`), returning `{"tracks":[...],"complete":false,"trackCues":{}}`. Only when the entire `Segment` is scanned to completion does Rust return `"complete": true` with populated `"trackCues"`. Swift `decodeBatchTracksOffMainActor` requires `response.complete == true` before admitting any track into `subtitleCache`.
  3. **Request-scoped cancellation lifecycle (`register -> cancel -> complete -> reclaim`), capacity rejection, per-category telemetry & XPC evidence classification**:
     - **Per-request identity (`request_id`) replaces global epoch**: Every embedded subtitle request allocates a monotonically increasing `request_id: UInt64` via `SubtitleSessionRequestRegistry` (`activePrewarmRequestID`, `activePrimaryRequestID`, `activeSecondaryRequestID`, `activeDefaultEmbeddedRequestID`). Cancelling pre-warm (`cancelSubtitlePrewarm()`), switching/cancelling primary (`selectSubtitle` / `loadExternalSubtitle`), or switching/cancelling secondary (`selectSecondarySubtitle`) cancels **only** its corresponding `request_id` (`ttmedia_subtitles_cancel_request(request_id)`), never interfering with concurrent primary/secondary loads or other sessions.
     - **Explicit 4-stage lifecycle (`register -> cancel -> complete -> reclaim`) — accepted requests retain cancellation state until explicit completion/reclamation**:
       - *Rust (`SubtitleRequestTable` in `subtitle_request_budget.rs`)*:
         1. **Accepted / In-Flight Active Table (`active_entries: HashMap<u64, Arc<ActiveRequestEntry>>`, `MAX_ACTIVE_REQUESTS = 4096`)**: Holds all registered (`ttmedia_subtitles_register_request`) and/or currently scanning (`begin_container_subtitle_request`) requests. **Crucial invariant**: when `cancel_container_subtitle_request(request_id)` is called on an already-registered request (`in_flight_scans == 0` or `in_flight_scans > 0`), it sets `active.cancelled = true` and **keeps the entry in `active_entries`** — it **never** removes an unstarted registered request from `active_entries` and **never** demotes it into `pre_start_tombstones`. Thus, in the sequence `register R -> cancel R -> >4096 other cancellations -> late start R`, `R` remains in `active_entries` with `cancelled = true`, its late scan start is guaranteed to be rejected (`clusters_scanned == 0`), and `R` is then removed from `active_entries` upon completion/reclamation (`ActiveRequestGuard::drop` or `ttmedia_subtitles_reclaim_request`).
         2. **Explicit Capacity Rejection (`MAX_ACTIVE_REQUESTS = 4096`)**: Existing accepted/active requests are **never** evicted or forgotten to make room for new requests. If `active_entries.len() >= MAX_ACTIVE_REQUESTS`, `ttmedia_subtitles_register_request` returns `false` and `begin_container_subtitle_request` returns `Err(io::ErrorKind::WouldBlock)` (`{"error":"Subtitle active request capacity exceeded (4096)"}`), explicitly rejecting the new request while preserving all 4096 existing requests.
         3. **Unregistered Pre-Start Tombstones (`pre_start_set`, `MAX_PRE_START_TOMBSTONES = 4096`), Pending Delays (`pending_delays`, `MAX_PENDING_DELAY_RECORDS = 256`), and Completed Telemetry (`completed_records`, `MAX_COMPLETED_RECORDS = 256`)**: `pre_start_set` is used strictly for out-of-order cancellations arriving before `register_request`. When a request completes or is reclaimed (`ActiveRequestGuard::drop` / `ttmedia_subtitles_reclaim_request`), its `active_entries`, `pre_start_set`, and `pending_delays` entries are removed and its final `(scanned_clusters, was_cancelled)` telemetry is archived in `completed_records` (`<= 256`). Rust exports per-category counters `ttmedia_subtitles_active_request_count()`, `ttmedia_subtitles_pre_start_tombstone_count()`, `ttmedia_subtitles_completed_record_count()`, `ttmedia_subtitles_pending_delay_count()`, and aggregate `ttmedia_subtitles_retained_record_count()`.
       - *Swift (`SubtitleSessionRequestRegistry` in `MediaSubtitleTransport.swift`, `MediaWorkerXPCTransport`, `MediaWorkerService`)*: Tracks `liveRequests: [UInt64: LiveRequest]` with hard capacity `maxActiveRequests = 4096` (no `unstartedOrder` silent eviction). `cancelRequest` and `cancelSession` mark registered `liveRequests` entries `isCancelled = true` **in place** without demoting them to `preStartTombstones`; new registrations beyond `maxActiveRequests` are explicitly rejected (`tryRegisterRequest` returns `false`, `beginRequest` throws `MediaWorkerError.readPacketFailed`); and `finishRequest(sessionId:requestID:)` deterministically reclaims both Swift and Rust state on every code path.
     - **Session isolation on stop/close**: Closing a session (`VideoPlaybackSession.stop()` -> `cancelAllSessionSubtitleRequests()`, `MediaWorkerDirectTransport.closeMedia`, `MediaWorkerXPCTransport.closeMedia`, `MediaWorkerService.closeMedia`) cancels and reclaims all requests belonging to that `sessionId` without affecting any new or concurrent session.
     - **End-to-end XPC request cancellation & evidence classification (`TTMediaWorkerProtocol`)**: `TTMediaWorkerProtocol` exports `subtitles(forSession:track:requestID:reply:)`, `cancelSubtitle(forSession:requestID:reply:)`, `configureSubtitleRequestDelay(forRequestID:delayMs:reply:)`, and `subtitleRequestStatus(forSession:requestID:reply:)`. Verification evidence is strictly classified into three distinct levels:
       1. *In-process `MediaWorkerDirectTransport`*: Verifies session/request lifecycle and native Rust cancellation within a single process.
       2. *In-process `NSXPCListener.anonymous()` + `MediaWorkerService` (`workerPid == getpid()`)*: Proves `NSXPCConnection` protocol serialization and method round-trip, but shares process memory and globals with the test host (`workerPid == getpid()`), so it is **not** counted as separate-process Worker evidence.
       3. *Out-of-process separate-PID Worker (`workerPid != getpid()`)*: Verified both via the bundled `TTMediaServiceSmokeHost.app` + `launchd`-spawned `TTMediaWorker.xpc` (`com.metastudyline.ttzip.smoke.media-worker`) over `NSXPCConnection` and via cross-PID subprocess Worker IPC in `TTMediaKitTests`, confirming that `workerPid != getpid()`, host-side `ttmedia_subtitles_last_scanned_clusters` remains `0`, cancelled single-track scan `reqA` (`track = 3`) stops mid-scan at `clustersScanned == 1` (`isCancelled == true`), concurrent single-track scan `reqB` (`track = 4`) in the same Worker continues and completes `clustersScanned == 2` (`2` cues), and scan status is returned over IPC.
  4. **Unified selection cancellation & cache-hit race prevention**: All primary (`loadExternalSubtitle`, `selectSubtitle`) and secondary (`selectSecondarySubtitle`) selection entry points unconditionally advance `subtitleLoadGeneration` / `secondarySubtitleLoadGeneration` and cancel only the corresponding previous primary/secondary request and prewarm request **before** evaluating `"off"` or `subtitleCache[id]`.

## Persistent presentation and safe positioned container extraction

Snapshots were rejected by actual window acceptance: the media session owns the live controller, clock, load task, subtitle catalog, track cache, active primary/secondary selections, and `SubtitleStyleConfiguration`. Viewports hold owner leases; resource reclamation waits a bounded 350ms after the final viewport releases.

Because read-only file descriptors in the current process cannot prevent external processes from modifying or truncating the underlying file, `container_subtitles.rs` avoids `unsafe` `memmap2` mapping and instead uses a safe 64 KiB positioned `FileExt::read_at` cache (`HeaderCache`). EBML VINTs, stack-decoded `uint` values, and short block payloads are served from `HeaderCache` while skipping uncached video payloads; if the file is truncated externally during scanning, `read_at` safely returns a recoverable `UnexpectedEof` error rather than risking `SIGBUS` or undefined behavior.

`TTMediaWorkerProtocol.subtitles(forSession:track:requestID:reply:)` (with 2-arg `subtitles(forSession:track:reply:)` compatibility wrapper), `cancelSubtitle(forSession:requestID:reply:)`, and `subtitleRequestStatus(forSession:requestID:reply:)` support four request modes on the validated read-only session descriptor:
- `track = -1`: reads only up to the first Cluster and returns the catalog `{"tracks":[{"id":3,"title":"中文","language":"zho","codec":"S_TEXT/UTF8","supported":true,"isDefault":true,"isForced":false}]}`.
- `track = 0`: performs a single-pass buffered `read_at` pre-warm scan across the Matroska/WebM Segment bounded by `MAX_PREWARM_TRACKS = 8` and `PREWARM_SCAN_BUDGET = 4s` (plus `request_id` cancellation). Returns `{"tracks":[...],"complete":true,"trackCues":{"3":[...]}}` when the full Segment is scanned, or `{"tracks":[...],"complete":false,"trackCues":{}}` if the budget expires or `request_id` cancellation occurs before `segment.end`.
- `track <= -2`: performs an encoded background pre-warm scan (`SubtitlePrewarmRequestCodec` / `try_encode_prewarm_request` / `decode_container_request`, rejecting `Int64.min` (`i64::MIN`) with an `InvalidInput` error rather than falling back to batch prewarm, and rejecting unrepresentable track IDs `<= 0` or `> UInt32.max`) carrying the **remaining time budget** (`budget_ms` in `1..=4000`), `max_tracks` (`1..=8`), and optional single `target_track_id` (used when only 1 pre-warm slot or 1 uncached embedded track remains, preventing bypass via `track > 0`). Returns the same `{"tracks":[...],"complete":true/false,"trackCues":{...}}` payload.
- `track > 0`: performs an explicit user-initiated full single-track scan `{"cues":[...]}` without pre-warm track-count or pre-warm time-budget truncation, aborting with `Interrupted` if cancelled via `ttmedia_subtitles_cancel_request(request_id)` (including over XPC via `cancelSubtitle(forSession:requestID:reply:)`).

Supported embedded codecs: `S_TEXT/UTF8`, `S_TEXT/ASCII`, `S_TEXT/WEBVTT`, `S_TEXT/ASS`, and `S_TEXT/SSA` across both Matroska `BlockGroup` and `SimpleBlock` elements.

## Subtitle style, dual-track & invariant viewport positioning

`SubtitleStyleConfiguration` persists user preferences in `UserDefaults` and drives `SubtitleOverlayView`:
- Primary & Secondary (bilingual) subtitle track rendering
- Font size (`14...48` pt, default `24`) and scale (`0.5...2.0`, default `1.0`), automatically scaled down in compact inspector viewports (`width < 380` pt)
- Bold / Italic weights, text color preset (White, Yellow, Cyan, Green)
- Outline border width (`0...4` pt, default `2.0`) and border color, plus background box opacity (`0...0.85`)
- Vertical position (`0...100`, default `90`) and subtitle delay (`-10.0...+10.0` s, step `0.1` / `0.5` s)
- **Control-visibility invariance**: `SubtitleOverlayView.bottomPadding` depends solely on viewport dimensions and `style.verticalPosition`, never on `controlsVisible`. Hovering in/out while paused or playing never shifts subtitle position.
- **No duplicate center play button**: Compact viewports (`width < 380` pt) rely exclusively on the bottom control bar without rendering a duplicate center play/pause button.
