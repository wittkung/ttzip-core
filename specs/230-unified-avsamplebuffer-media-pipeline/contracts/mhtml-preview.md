# MHTML offline preview contract (2026-10-24)

## User scenario
Selecting a saved `.mhtml` or `.mht` page displays its decoded HTML by default, including supported bundled styles and images. Source mode retains the original MIME document and never overwrites it with decoded HTML.

## Boundary
- Existing `ttmedia_mhtml_extract_summary` JSON adds optional `rendered_html`; existing fields and allocation/free ownership remain unchanged. Older payloads without the field decode successfully.
- Rust owns multipart parsing, transfer decoding (quoted-printable, base64, 7bit/8bit), root selection and bundled-resource embedding. Swift owns presentation and offline WebKit policy.
- Decode at most 8 MiB input/output, 256 parts, 16 KiB headers per part. Unsupported or malformed archives retain source inspection. No network or filesystem reads during MIME resolution.
- The root is selected by `start` Content-ID when specified, otherwise the first HTML part. Supported bundled images/fonts/styles use data URLs; unresolved resources remain blocked by the offline policy.
- HTML containing inline SVG remains an HTML document, not an SVG canvas.
- Both compressed `.svgz` validation (`infra/ttmedia/src/svgz.rs::contains_valid_svg_element`) and standalone SVG canvas selection (`HTMLWKWebViewRepresentable.isStandaloneSVG`) enforce the same bounded lexical document-root `<svg` opening-tag identity contract (not full XML well-formedness validation): scan only the document preamble boundary (optional UTF-8 BOM, whitespace, XML processing instructions `<?...?>`, comments `<!--...-->`, and `<!DOCTYPE ...>` including optional internal `[...]` subset) before the very first root element opening tag, which must be an unprefixed ASCII case-insensitive `<svg` followed immediately by whitespace, `'/'`, or `'>'` and closed by `'>'` outside single/double quotes. Neither layer trusts a `.svg`/`.svgz` file extension without root `<svg` verification (except `isStandaloneSVG`'s empty-`content` URL load placeholder before `loadHTML` resolves and verifies the payload), and neither parses/expands XML entities, reads external DTDs, or performs network I/O. When `loadHTML` resolves an empty-`content` local `.svgz` URL and `SVGZBoundedDecompressor.decompressSVGZ(from:)` rejects the payload (bad CRC, truncated stream, size/ratio budget exceeded, or non-`<svg` root), `loadHTML` renders the escaped read-only `<pre>` fallback (`sourceFallbackHTML` under offline CSP with `allowedDocumentURL = nil` and `baseURL: nil`) and never calls `webView.loadFileURL` on the rejected `.svgz` file.
- Standalone SVG envelope (`loadSVGEnvelope`) reads `viewBox`, `width`, and `height` strictly from the root `<svg ...>` opening tag (handling quoted `>`), never from child `<symbol>`, `<rect>`, or comments; preserves any existing root `viewBox`; synthesizes `viewBox="0 0 W H"` only when both root `width` and `height` are positive finite user-unit or `px` values (never equating `pt`, `cm`, `%`, or relative units with user coordinates), serializing each finite `Double` via `Int(exactly:)` fallback to `String(Double)` so large finite values (e.g. `1e100`) neither trap on `Int` overflow nor clamp to `Int.max`. Envelope CSS scopes `width: 100% !important; height: 100% !important; max-width: 100%; max-height: 100%; object-fit: contain; margin: auto;` to `body > svg[viewBox]`, while `body > svg:not([viewBox])` uses `margin: auto; flex-shrink: 0;` inside `html, body { display: flex; overflow: auto; }` (where `document.body` is the inner overflow scroll owner exposing `scrollWidth`/`scrollHeight` and `scrollLeft`/`scrollTop`) so non-`viewBox` physical-unit graphics (`pt`, `cm`, etc.) preserve WebKit's native CSS intrinsic dimensions, center when smaller than `body`'s client box, and remain unclipped and scrollable via `document.body` when larger than the viewport.
- Compressed `.svgz` source mode (`HTMLWebRichPreviewView`) distinguishes the compressed Gzip container from the decompressed UTF-8 SVG text: `CodeTextEditorContainerView` receives the decompressed in-memory UTF-8 text as read-only (`fileURL: nil`, `isReadOnly: true`, `initialByteCount: Int64(content.utf8.count)`) with a derived `TTPreviewResourceContext` (`.withDerivedRepresentation(true, description: "SVGZDecompressedSource").withReadableURL(nil)`) that preserves archive origin identity when present while preventing `TTTextSourceInspection` from re-reading Gzip bytes or writing back to the `.svgz` container.
- Existing nonpersistent WebKit data store, disabled page scripts, offline CSP and navigation restrictions apply to the decoded document.

## Validation
- Rust: transfer decoding, root selection, resources, malformed input and budgets.
- Swift: disk/async/memory route parity, original source preservation and optional JSON compatibility.
- WebKit: DOM text, bundled CSS/image rendering, inline SVG and page script isolation; opt-in real saved-page fixture.
- Build the TTZip application and run the repository gate; record blockers separately from targeted results.
